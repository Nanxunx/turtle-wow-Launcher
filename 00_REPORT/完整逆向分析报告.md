# Turtle WoW Launcher `turtle-wow(6).exe` 完整静态拆解报告

## 0. 结论

这个样本是 **Windows x86-64 / Rust / Tauri 2.x / React** 启动器，不是 .NET、Electron 或传统 C# WinForms/WPF。最重要的发现是：EXE 中嵌入了 3 套前端 JavaScript source map，并且 `sourcesContent` 存在，因此**当前生效前端的 124 个项目源文件可按原 TypeScript/TSX 内容恢复**。当前 `index.html` 只加载 `index-D4LZleiB.js` 和 `index-Bw3YQ_ue.css`；另外两套 JS/map 是残留历史构建。

Native Rust 后端没有 source map，PDB 仅泄漏文件名 `turtle_wow.pdb` 而没有可用符号文件，所以 Rust 部分只能做高可信静态重建，不能伪称“原始源码”。

> 安全处理：样本前端包含一个写死的 Stronghold vault 解锁字面量。它可能用于解锁本机保存的登录 token，属于凭据性质信息。本交付包中已统一替换为 `[REDACTED_APP_VAULT_KEY]`，但其存在位置和风险仍完整记录。Native StormLib 代码区还静态包含其已公开的 Blizzard weak MPQ signing 私钥常量；本包不复制、导出或复述任何私钥正文，只记录来源、偏移、用途和风险。除此之外，构建机器用户名也只做了轻度脱敏，不影响技术分析。

PE Security Directory 为 offset `0x1F71C00` / size `0x26E8`。最终 byte-level 复核确认当前样本大小正好为 `0x1F71C00 + 0x26E8`，因此该 9,960-byte `WIN_CERTIFICATE` 完整存在。PKCS#7 叶子代码签名证书 Subject 为 `O=Turtle WoW, CN=Turtle WoW`，Issuer 为 `Sectigo Public Code Signing CA EV R36`；独立按 Authenticode 规则重算 SHA-256 与 `SpcIndirectDataContent` 内 digest 完全一致。详见 `10_NATIVE_ULTIMATE/AUTHENTICODE_FORENSICS.md`。

## 7. 更新器核心算法

Manifest schema：file 类型 `file/del/cache/mpq`；字段 name/type/hash/size/mtime/tags/mirrors；patch 含 key/name/files/fullArchive。

验证阶段：
1. 检查 path 长度（Windows 上限逻辑 220）。
2. 可选清 `.partial` + `file-cache.json`。
3. 先验证 launcher 自身更新。
4. 并行取 client manifest、language patch、mods manifest。
5. 已启用官方 DLL mod 文件并入 client manifest；禁用则把其文件变成 `del`。
6. 多 worker round-robin queue，默认并发 `max(2,min(6,floor(hardwareConcurrency/2)))`。
7. 普通文件以 hash+mtime cache 调 Native `verify_file`；`allowExtra` 跳过；`allowModified` 允许本地修改。
8. `WoW.exe` 特殊：若本地 build >= manifest `build:` tag，跳过覆盖。
9. MPQ：优先 hash fullArchive；否则 `verify_mpq` 文件级验证。如果需要下载的数据 >= fullArchive 的 75%，改为整包下载。
10. 汇总下载大小并检查磁盘空间。

更新阶段：
- `del` 删除；普通文件 `update_file`；MPQ `update_mpq`。
- 进度 Channel 有 initial/progress/revert/finalizing/fileDone/mpqBuild。
- 速度基于最近约 10 秒样本，最多保留 50 samples，估 ETA。
- 下载后清 WDB、重查 Data、清 `.partial`、再次 `Patcher.applyAll()`。

Native fetcher 有 HEAD/Content-Length/Range/partial/resume/hash/mirror retry/timeout。其错误字符串证明 hash mismatch 会自动尝试恢复，不是一条 URL 失败就立即终止。

Launcher self-update：fetch `/api/launcher/TurtleWoW.<exe|AppImage>[?beta]` → 下载 installer → `prepare_self_update`（Native 有 PE signature verify）→ `run_detached` → 关闭当前 launcher。

## 9. Auth / 本地敏感数据

生产模式：AppData 下 `vault.hold`，Stronghold client 名 `AuthClient`。账号键格式 `<username>@<region>`，token 作为 value 存 Stronghold；`preferences.json` 只存 account 名/savedAccounts 等非 token 状态。开发模式用 `dev-auth.json` 明文存储。

发现一个**写死在前端 bundle/source map 中的 Stronghold unlock 字面量**。因为它可配合本地 `vault.hold` 解锁会话 token，本包不提供原值，而用 `[REDACTED_APP_VAULT_KEY]`。这是最值得修复的安全设计问题之一：Stronghold 的保护收益会被静态内嵌 unlock secret 显著削弱。

登录 POST `/api/auth`，body 为 username/password/oneTimeCode，region 放 `X-Server`；成功保存 token。authenticate GET `/api/auth`；signout DELETE `/api/auth`。UI 对 account 名做星号匿名化，日志还会把 `C:\Users\<name>\` 和 `/home/<name>/` 脱敏成 `<USERNAME>`。

### StormLib 内嵌 MPQ 签名密钥材料

在原始 EXE 的 `.rdata` 可定位到 PKCS#8 PEM private-key header，起始文件偏移约 `0x19A0630`；紧随其后还存在多组 PEM public-key headers。通过与 StormLib 官方 `src/SFileVerify.cpp` 对照，这一组常量可以**精确归因**为 StormLib 的 `szBlizzardWeakPrivateKey`、`szBlizzardWeakPublicKey` 及 Blizzard/Warcraft/WoW/StarCraft MPQ 验签公钥集合。StormLib 使用该 weak private key 对 MPQ 的弱签名（MD5 + 512-bit RSA）执行签名。

这不是 Turtle WoW 登录账号的 token、服务器 API secret，也不是当前 EXE 的 Authenticode 私钥；它是被静态链接进二进制的 StormLib/MPQ 依赖常量。因为它仍属于私钥材料，交付包**只记录存在性和归因，不包含 PEM 正文**。当前 StormLib 官方源码本身公开了该历史 key，这也解释了为什么它会出现在静态链接样本中。

原始样本内还能找到一个 RSA private-key PEM format marker 文本标记（约 `0x19F5898`）；静态上下文归属于 libssh2/PEM parser 一类错误/格式字符串，未观察到跟随的对应私钥 PEM 主体，因此不能把它当作第二把实际私钥。

## 17. 风险/异常点（只陈述证据）

1. **Stronghold unlock secret 静态内嵌**：安全边界较弱，已在交付中红acted。
2. **Self-update 设计有签名校验**：`signature_check` 先要求 `pe-sign` 验证状态为 `Valid`，再提取证书 Subject `CN=`；`update_file` 对可执行更新要求 signer 精确等于 `Turtle WoW`。当前样本自身也带完整 Authenticode `WIN_CERTIFICATE`，叶子证书 `O=Turtle WoW, CN=Turtle WoW`。
3. **直接二进制 patch WoW.exe**：依赖固定 offsets；若游戏 EXE build 与偏移表不匹配存在写错位置风险。Updater 对 WoW build 有自己的判断，但 patcher 本身未显示逐 offset signature guard。
4. **Dev mode 权限很强**：自定义 server URL、Dev API secret、Git push、build/extract MPQ、运行 VS Code、可强制关游戏；这是明确的开发功能，不应与普通玩家面混用。
5. **残留 source maps 导致源码完整泄漏**：生产 EXE 内同时保留三套带 `sourcesContent` 的 map，直接暴露业务逻辑、隐藏 Dev UI、接口、auth 实现和更新策略。
6. **StormLib weak signing private key 随静态链接进入 EXE**：已确认是 StormLib 官方源码中的历史 Blizzard weak MPQ signing key，而非本项目登录凭据；交付包不包含 key 正文。

## 18. “原始结构”能恢复到什么程度

**可视为原始内容：** active 的 TS/TSX `sourcesContent`、三套前端 map、active/历史编译 bundle、CSS、图片/字体、6 套 locale 值、index.html。

**高可信重建但不是原始源文件：** Rust command contracts、Rust module file names、下载/Git/MPQ/self-update 逻辑。

**无法从这个单独 EXE 无损恢复：** 开发者未打进 source map 的 `package.json`/lockfile、完整 `tauri.conf.json`/capabilities 文件、Cargo.toml、原始 Rust 源码、Git history/commit hash（除 StormLib checkout 线索）、原始注释/局部变量（Native）、构建 CI 配置、服务端 API 实现。

这不是分析遗漏，而是信息在该二进制中没有以可逆形式存在。

## 20. 第二阶段 Native 深挖补充（GitHub final）

第二阶段使用 `.pdata` 函数边界 + Rust `&str` descriptor XREF 与 Tauri command literal XREF 恢复出 28 个项目相关 Native 根函数，并建立全映像调用图与 IPC dispatch 映射。逐文件成果见 `09_NATIVE_DEEP_DIVE/`。

新增关键证据：`src/updater/signature_check.rs` 的真实函数位于 `0x140006C30–0x14000725F`；机器码遍历签名证书属性并搜索 `CN=`。`update_file` 对 `.exe/.dll` 的安全路径直接调用该函数，随后把 signer 与 `Turtle WoW` 做精确比较，并存在 `TURTLE_SIGNATURE` 16-byte 条件比较。故自更新/可执行更新的 Native 安全模型现已从“存在 pe-sign”提升到“可定位的 signer-CN 验证控制流”。
